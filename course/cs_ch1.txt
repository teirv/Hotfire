=L cs1b | Variables and types
@T
C# is **statically typed**: every variable has a type, and it can't change.

`int` is a whole number, `double` is a decimal, `string` is text, `bool` is `true` or `false`, and `char` is one character in single quotes.

`var` lets C# work out the type from the value. The type is still fixed.
~code
int parts = 12;
double psi = 450.5;
string name = "Valve";
bool ok = true;
char grade = 'A';
var count = 3;

Console.WriteLine($"{name}: {parts} parts at {psi} psi, ok = {ok}, grade {grade}, count {count}");
@T
`$"..."` is an **interpolated string**. Values go inside `{ }`. Add a format after a colon: `{psi:F1}` gives 1 decimal place.

Division between two `int`s drops the remainder. Make one side a `double` to keep it.
~code
int a = 7;
int b = 2;
Console.WriteLine(a / b);
Console.WriteLine(a % b);
Console.WriteLine((double)a / b);
Console.WriteLine($"{2.0 / 3:F2}");
@P
What does this print?
~code
int total = 10;
int people = 4;
Console.WriteLine(total / people);
~opts
* 2
- 2.5
- 3
~why
Both are `int`, so the decimal part is dropped. It doesn't round.
@Q
Which line won't compile?
~opts
* `int x = "5";`
- `var y = 5;`
- `double z = 5;`
~why
A string can't go into an `int`. A whole number can go into a `double`.
@B
Make a variable that holds `true` or `false`.
~code
___ isOpen = false;
~opts
* bool
- boolean
- string
~why
In C# it's `bool`. Java uses `boolean`.

=L cs2a | if and else
@T
Comparisons give a `bool`: `==`, `!=`, `<`, `>`, `<=`, `>=`.

Combine them with `&&` (and), `||` (or), and `!` (not).

The condition goes in parentheses, and the code in braces.
~code
int psi = 520;

if (psi > 500)
{
    Console.WriteLine("Over limit");
}
else if (psi >= 450)
{
    Console.WriteLine("Near limit");
}
else
{
    Console.WriteLine("Normal");
}
@T
The **ternary** operator picks one of two values in one line: `condition ? a : b`.

Strings compare with `==` in C#, which checks the text itself.
~code
int fuel = 30;
string status = fuel > 50 ? "Good" : "Refuel";
Console.WriteLine(status);
Console.WriteLine("go" == "go");
@P
What does this print?
~code
int x = 7;
if (x > 5 && x < 10)
{
    Console.WriteLine("In range");
}
else
{
    Console.WriteLine("Out");
}
~opts
* In range
- Out
- In range
Out
~why
Both sides of `&&` are true.
@B
Print `Even` or `Odd` in one line.
~code
int n = 4;
Console.WriteLine(n % 2 == 0 ___ "Even" ___ "Odd");
~opts
* ?
* :
- &&
- ||
~why
`condition ? valueIfTrue : valueIfFalse`
~out

=L cs2b | switch
@T
`switch` picks a branch based on one value. Each `case` ends with `break`. `default` runs when nothing matches.
~code
string day = "Sat";

switch (day)
{
    case "Sat":
    case "Sun":
        Console.WriteLine("Weekend");
        break;
    default:
        Console.WriteLine("Weekday");
        break;
}
@T
A **switch expression** is a shorter version that gives back a value. `_` means anything else.
~code
int code = 404;
string meaning = code switch
{
    200 => "OK",
    404 => "Not found",
    500 => "Server error",
    _ => "Unknown",
};
Console.WriteLine(meaning);
@Q
In a regular `switch` statement, what ends each case?
~opts
* `break;`
- `end;`
- Nothing
~why
C# won't let one case fall into the next unless it's empty.
@P
What does this print?
~code
int level = 3;
string name = level switch
{
    1 => "Low",
    2 => "Medium",
    _ => "High",
};
Console.WriteLine(name);
~opts
* High
- Medium
- Low
~why
3 doesn't match 1 or 2, so `_` catches it.

=L cs3a | for and while
@T
A `for` loop has three parts: start, keep-going test, and step. `i++` adds 1.

A `while` loop runs as long as its condition is true.
~code
for (int i = 1; i <= 3; i++)
{
    Console.WriteLine($"Round {i}");
}

int tank = 0;
while (tank < 100)
{
    tank += 40;
}
Console.WriteLine(tank);
@T
`break` leaves a loop early. `continue` skips to the next round.

A `do`/`while` loop always runs at least once, because it checks at the end.
~code
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0) continue;
    if (i > 7) break;
    Console.Write(i + " ");
}
Console.WriteLine();
@P
How many lines does this print?
~code
for (int i = 0; i < 4; i++)
{
    Console.WriteLine(i);
}
~opts
* 4
- 3
- 5
~why
0, 1, 2 and 3.
@P
What does this print?
~code
int n = 1;
while (n < 20)
{
    n *= 3;
}
Console.WriteLine(n);
~opts
* 27
- 9
- 20
~why
1, 3, 9, then 27 stops the loop.

=L cs4a | Writing methods
@T
A **method** is a named block of code. Its first word is the type it returns, or `void` if it returns nothing. Each parameter has a type too.

In this style of program, methods can sit below the code that calls them.
~code
Console.WriteLine(Area(3, 4));

{
    return width * height;
}

void Greet(string name)
{
    Console.WriteLine($"Hi, {name}");
}

A one-line method can use `=>`. Parameters can have default values.
~code
double Square(double x) => x * x;
string Label(string text, string unit = "psi") => $"{text} {unit}";

Console.WriteLine(Label("450"));
Console.WriteLine(Label("31", "bar"));

=L cs4b | Overloads, out and ref
@T
**Overloading** means several methods share a name but take different parameters. C# picks the right one.

Overloads must live inside a class. A `static class` is a simple home for related tools, and you call them with the class name in front.
~code
Console.WriteLine(Tools.Add(2, 3));
Console.WriteLine(Tools.Add(2.5, 1.25));

static class Tools
{
    public static int Add(int a, int b) => a + b;
    public static double Add(double a, double b) => a + b;
}
@T
Normally a method gets a copy of a number. `ref` lets it change the caller's variable. `out` lets it hand back an extra result.

`int.TryParse` uses `out`: it returns `true` or `false`, and puts the number in the `out` variable.
~code
int score = 10;
Bonus(ref score);
Console.WriteLine(score);

if (int.TryParse("42", out int n))
{
    Console.WriteLine(n + 1);
}
Console.WriteLine(int.TryParse("abc", out int bad));

void Bonus(ref int s) => s += 5;
@Q
Why use `int.TryParse` instead of `int.Parse`?
~opts
* It doesn't crash on bad input
- It's the only way to read numbers
- It rounds decimals
~why
`int.Parse("abc")` throws an exception. `TryParse` returns `false`.
