=L cs5a | List and Dictionary
@T
A `List<T>` is like an array that can grow. `T` is the type it holds: `List<string>` holds text.

`Add`, `Remove`, `Contains`, and `Count` are the everyday tools.
~code
var parts = new List<string> { "valve", "seal" };
parts.Add("hose");
parts.Remove("seal");

Console.WriteLine(parts.Count);
Console.WriteLine(parts.Contains("hose"));
Console.WriteLine(string.Join(", ", parts));
@T
A `Dictionary<TKey, TValue>` maps keys to values. Reading a missing key throws an error, so check with `ContainsKey` or use `TryGetValue`.
~code
var stock = new Dictionary<string, int>
{
    ["valve"] = 3,
    ["seal"] = 12,
};
stock["hose"] = 5;
stock["valve"] += 1;

foreach (var pair in stock)
{
    Console.WriteLine($"{pair.Key}: {pair.Value}");
}
Console.WriteLine(stock.ContainsKey("pump"));
@P
What does this print?
~code
var list = new List<int> { 4, 8 };
list.Add(15);
list.RemoveAt(0);
Console.WriteLine(list.Count + " " + list[0]);
~opts
* 2 8
- 3 4
- 2 4
~why
`RemoveAt(0)` removes by position, so 8 moves to the front.
@Q
What does `new Dictionary<string, int>()["missing"]` do?
~opts
* Throws a `KeyNotFoundException`
- Returns 0
- Returns null
~why
Use `TryGetValue` or `ContainsKey` first.
=L cs5b | LINQ
@T
**LINQ** gives lists query tools. `Where` keeps matching items, `Select` changes each item, and `OrderBy` sorts. `Sum`, `Average`, `Max`, `Count` and `Any` summarize.

`x => x > 10` is a **lambda**: a tiny function. Read it as "for each x, is x over 10?"
~code
var readings = new List<int> { 5, 12, 8, 30 };

var high = readings.Where(x => x > 10).ToList();
var doubled = readings.Select(x => x * 2);

Console.WriteLine(string.Join(",", high));
Console.WriteLine(string.Join(",", doubled));
Console.WriteLine(readings.Sum());
Console.WriteLine(readings.Max());
Console.WriteLine(readings.Any(x => x > 25));
@P
What does this print?
~code
var a = new List<int> { 1, 2, 3, 4 };
Console.WriteLine(a.Where(x => x % 2 == 0).Sum());
~opts
* 6
- 10
- 4
~why
It keeps 2 and 4, then adds them.
@B
Get the names of parts in order.
~code
var names = parts.___(p => p.Name).___(n => n).ToList();
~opts
* Select
* OrderBy
- Where
- Sum
~why
`Select` picks the names, and `OrderBy` sorts them.

=U csclass | Classes and Objects | Your own types.
=L cs6a | Classes, fields and constructors
@T
A **class** is a blueprint. Each object made from it has its own data.

A **constructor** has the same name as the class and runs when you use `new`. `public` means other code can use it.

Classes go below your other code.
~code
var t = new Tank("T-1", 500);
t.Fill(120);
Console.WriteLine(t.Describe());

class Tank
{
    public string Name;
    public int Capacity;
    public int Level;

    public Tank(string name, int capacity)
    {
        Name = name;
        Capacity = capacity;
    }

    public void Fill(int liters)
    {
        Level = Math.Min(Capacity, Level + liters);
    }

    public string Describe() => $"{Name}: {Level}/{Capacity} L";
}
@T
**Properties** are the C# way to expose data. `{ get; set; }` makes a property you can read and change. `{ get; }` makes it read-only after construction.

A property can also compute its value with `=>`.
~code
var r = new Rect(3, 4);
Console.WriteLine(r.Area);
r.Width = 10;
Console.WriteLine(r.Area);

class Rect
{
    public int Width { get; set; }
    public int Height { get; }
    public int Area => Width * Height;

    public Rect(int w, int h)
    {
        Width = w;
        Height = h;
    }
}
@Q
When does a constructor run?
~opts
* When you create an object with `new`
- Every time a method is called
- When the program ends
~why
It sets the object up.
@P
What does this print?
~code
var a = new Box();
var b = a;
b.Size = 9;
Console.WriteLine(a.Size);

class Box { public int Size { get; set; } }
~opts
* 9
- 0
- An error
~why
Classes are **reference types**. `a` and `b` point to the same object.
@B
Make a property you can read but only set in the constructor.
~code
public string Id { ___; }
~opts
* get
- set
- readonly
~why
Without `set`, outside code can't change it.
=L cs6b | ToString, static and records
@T
Every class has `ToString()`, which is used when you print an object. **Override** it to print something useful.

`static` members belong to the class, not to each object. They're shared by all objects.
~code
var a = new Part("valve");
var b = new Part("seal");
Console.WriteLine(a);
Console.WriteLine(Part.Made);

class Part
{
    public static int Made = 0;
    public string Name { get; }

    public Part(string name)
    {
        Name = name;
        Made++;
    }

    public override string ToString() => $"Part({Name})";
}
@T
A **record** is a short way to make a class mostly for holding data. It prints nicely, and two records with the same values are equal.
~code
var p1 = new Point(1, 2);
var p2 = new Point(1, 2);
Console.WriteLine(p1);
Console.WriteLine(p1 == p2);

record Point(int X, int Y);
@Q
What's a good use for `static`?
~opts
* A counter shared by every object of a class
- A value that's different for each object
- A method that must be overridden
~why
There's only one copy of a static member.

=U csoop | Inheritance and Interfaces | Sharing and promising behavior.
=L cs7a | Inheritance
@T
A class can **inherit** from another with `:`. It gets the parent's members.

Mark a method `virtual` to allow children to replace it, and `override` in the child. `base(...)` calls the parent's constructor.
~code
Animal[] pets = { new Dog("Rex"), new Cat("Tom") };
foreach (var p in pets)
{
    Console.WriteLine(p.Speak());
}

class Animal
{
    public string Name { get; }
    public Animal(string name) { Name = name; }
    public virtual string Speak() => $"{Name} makes a sound";
}

class Dog : Animal
{
    public Dog(string name) : base(name) { }
    public override string Speak() => $"{Name} barks";
}

class Cat : Animal
{
    public Cat(string name) : base(name) { }
}
@Q
Refer to the code above. `Cat` doesn't override `Speak`. What does `new Cat("Tom").Speak()` return?
~opts
* Tom makes a sound
- Tom barks
- An error
~why
It uses the parent's version.
@Q
What do you need on a parent method so a child can override it?
~opts
* `virtual` (or `abstract`)
- `static`
- `private`
~why
C# makes overriding something you opt into.
=L cs7b | Interfaces and abstract classes
@T
An **interface** is a promise: any class that implements it must have these members. Interface names start with `I` by convention.

An **abstract** class can't be created directly. Its abstract methods must be filled in by children.
~code
IShape[] shapes = { new Square(3), new Circle(1) };
foreach (var s in shapes)
{
    Console.WriteLine($"{s.Name}: {s.Area():F2}");
}

interface IShape
{
    string Name { get; }
    double Area();
}

class Square : IShape
{
    private double side;
    public Square(double s) { side = s; }
    public string Name => "Square";
    public double Area() => side * side;
}

class Circle : IShape
{
    private double r;
    public Circle(double radius) { r = radius; }
    public string Name => "Circle";
    public double Area() => Math.PI * r * r;
}
@Q
How many interfaces can one class implement?
~opts
* As many as it needs
- Only one
- None, only abstract classes
~why
A class can inherit from only one class, but implement many interfaces.
@Q
What happens with `new IShape()`?
~opts
* It won't compile
- It makes an empty shape
- It returns null
~why
Interfaces can't be created directly. Only classes that implement them can.

=U cserr | Errors and Null | Handling the unexpected.
=L cs8a | Exceptions
@T
When something goes wrong, C# **throws** an exception. `try` and `catch` handle it. Catch specific types first. `finally` always runs.
~code
string[] inputs = { "12", "abc" };
foreach (var text in inputs)
{
    try
    {
        int n = int.Parse(text);
        Console.WriteLine(100 / (n - 12));
    }
    catch (FormatException)
    {
        Console.WriteLine($"'{text}' isn't a number");
    }
    catch (DivideByZeroException)
    {
        Console.WriteLine("Can't divide by zero");
    }
    finally
    {
        Console.WriteLine("Checked");
    }
}
@T
Throw your own with `throw new ExceptionType("message")`. `ArgumentException` is the usual one for bad input. `e.Message` holds the text.
~code
try
{
    SetValve(150);
}
catch (ArgumentException e)
{
    Console.WriteLine(e.Message);
}

void SetValve(int percent)
{
    if (percent < 0 || percent > 100)
        throw new ArgumentException("Percent must be 0 to 100");
}
@P
What does this print?
~code
try
{
    Console.WriteLine("A");
    throw new Exception("x");
}
catch (Exception)
{
    Console.WriteLine("B");
}
finally
{
    Console.WriteLine("C");
}
~opts
* A
B
C
- A
C
- B
C
~why
The throw jumps to catch, and finally always runs.

Console.WriteLine(name ?? "Unknown");

@P
What does this print?
~code

Console.WriteLine((city ?? "none").ToUpper());
~opts
* NONE
- null
- An error
~why
`??` swaps in "none" before `ToUpper` runs.
