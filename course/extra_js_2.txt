=L xwebjs | Going deeper: where scripts go
@T
Three ways to load a script, and when each one runs:

`<script>` in the `<head>`: runs right away, **before** the body exists, so it can't find elements.

`<script>` at the end of `<body>`: runs after the page above it is built.

`<script defer src="app.js">`: downloads early, runs after the whole page is read. This is the usual modern choice.
@Q
Which choice lets a script in the `<head>` safely use elements in the body?
~opts
* `<script defer src="app.js"></script>`
- `<script async-body src="app.js"></script>`
- `<script src="app.js" head></script>`
~why
`defer` waits for the page. `async` also exists, but runs as soon as it downloads.
@Q
Why keep JavaScript in a separate `.js` file?
~opts
* The browser can cache it, and many pages can share it
- Inline scripts are slower to type
- HTML can't hold JavaScript
~why
It also keeps HTML focused on content.

- The first two calls had errors
~why
Only the last timer survives long enough to run.
