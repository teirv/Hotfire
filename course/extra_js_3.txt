=L xjq1 | Going deeper: jQuery vs plain JavaScript
@T
jQuery is shorter, but modern browsers can do the same things. Knowing both helps you read older code and write new code.

`$("#a")` is like `document.querySelector("#a")`. `$(".x").addClass("on")` is like looping over `querySelectorAll(".x")` and calling `classList.add("on")`.

`$(el)` wraps a plain element, and `$(".x")[0]` or `.get(0)` unwraps it.
~html
<p class="x">One</p><p class="x">Two</p>
~code
$(".x").addClass("on");

document.querySelectorAll(".x").forEach((el) => el.classList.add("plain"));

console.log($(".x").first().attr("class"));
console.log($(".x")[0] === document.querySelector(".x"));
@Q
Refer to the code above. What's the plain JavaScript version of `$("#a").text("Hi")`?
~opts
* `document.querySelector("#a").textContent = "Hi";`
- `document.text("#a", "Hi");`
- `$("#a").textContent = "Hi";`
~why
A jQuery object doesn't have `textContent`. Unwrap it, or use `.text()`.

=L xjq2 | Going deeper: event details
@T
jQuery handlers get an event object too. `e.preventDefault()` stops a link or form's normal action, and `$(this)` is the element that was used.

`.off("click")` removes handlers, and `.one("click", fn)` runs only once.
~html
<a id="go" href="https://example.com">Go</a>
<button id="once">Once</button>
<p id="out"></p>
~code
$("#go").on("click", (e) => {
  e.preventDefault();
  $("#out").text("Link blocked");
});

let n = 0;
$("#once").one("click", () => $("#out").text("Clicked " + ++n));
$("#once").trigger("click");
$("#once").trigger("click");
console.log($("#out").text());
@Q
Refer to the code above. Why does the text say `Clicked 1` after two clicks?
~opts
* `.one` removes the handler after the first time
- `trigger` only works once
- `n` resets
~why
That's what `one` is for.

=L xjq4 | Going deeper: $.ajax options
@T
`$.ajax` takes one settings object. The key settings are `url`, `method`, `data` (sent as query values for GET), and `dataType`. It returns a promise-like object, so `await` works too.
~html
<p id="w"></p>
~code
async function run() {
  let data = await $.ajax({
    url: "https://api.example.com/weather",
    method: "GET",
    data: { city: "Seattle" },
    dataType: "json",
  });
  console.log(data.condition);
}
run();
@Q
Refer to the code above. What does `data: { city: "Seattle" }` do for a GET request?
~opts
* Adds `?city=Seattle` to the URL
- Sends a JSON body
- Saves the city to storage
~why
jQuery builds the query string for you.
