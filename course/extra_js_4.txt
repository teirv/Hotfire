=L xng1 | Going deeper: how an Angular app starts
@T
When you run `ng serve`, the CLI builds your TypeScript into JavaScript and serves it. The browser loads `index.html`, which contains a tag like `<app-root>`. Angular finds the component with that selector and draws it.

```
// main.ts
bootstrapApplication(AppComponent);
```
@Q
What connects `<app-root>` in `index.html` to your code?
~opts
* The component's `selector: "app-root"`
- The file name `app-root.html`
- A script tag with that id
~why
Selectors are how Angular finds where each component goes.

=L xre1 | Going deeper: what JSX becomes
@T
JSX is not HTML. A build tool turns each tag into a function call. This is why JSX can sit anywhere a value can.

```
const el = <p className="tip">Hi {name}</p>;

// becomes roughly:
const el = React.createElement("p", { className: "tip" }, "Hi ", name);
```
@Q
Why must a component return one parent element?
~opts
* A function can only return one value
- Browsers require it
- CSS needs a wrapper
~why
Use `<>...</>` (a fragment) to group without adding a real element.

=L xre2 | Going deeper: state updates
@T
State updates don't happen instantly. React schedules a re-render. When the new value depends on the old one, pass a function to the setter.

```
// Might only add 1, because count is read twice from the same render
setCount(count + 1);
setCount(count + 1);

// Always adds 2
setCount(c => c + 1);
setCount(c => c + 1);
```
@Q
Refer to the code above. Why does the function form work?
~opts
* React passes each update the latest value
- Arrow functions are faster
- It skips re-rendering
~why
Use it whenever the next state depends on the previous one.
