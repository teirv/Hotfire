=L xpymath | Going deeper: rounding rules
@T
Python's `round()` uses **banker's rounding**: a value exactly halfway goes to the nearest even number. So `round(2.5)` is 2, and `round(3.5)` is 4.

For money, format with an f-string instead: `f"{x:.2f}"`.

`abs()` drops a minus sign, and `divmod(a, b)` gives `//` and `%` together.
~code
print(round(2.5), round(3.5), round(2.675, 2))
print(f"{2.675:.2f}")
print(divmod(135, 60))
print(abs(-12.5))
@Q
Refer to the code above. What does `divmod(135, 60)` return?
~opts
* `(2, 15)`
- `2.25`
- `(15, 2)`
~why
It's `(135 // 60, 135 % 60)`.
@P
What does this print?
~code

~opts
* 4
- 5
- 4.5
~why
Halfway values go to the even number.

=L xpyloop | Going deeper: loop patterns
@T
Most loop problems are one of three patterns:

**Accumulate:** start a total at 0 and add to it.

**Count:** start at 0 and add 1 when something matches.

**Find the best:** start with the first value and replace it when you find a better one.
~code
nums = [4, 17, 9, 22, 3]
total = 0
evens = 0
biggest = nums[0]
for n in nums:
    total += n
    if n % 2 == 0:
        evens += 1
    if n > biggest:
        biggest = n
print(total, evens, biggest)
@Q
Refer to the code above. Why start `biggest` at `nums[0]` instead of 0?
~opts
* If every number were negative, 0 would be wrong
- 0 isn't allowed
- It makes the loop shorter
~why
Starting with a real value from the list is always safe.

=L xpyerr | Going deeper: which except runs
@T
Python checks `except` blocks from top to bottom and runs the **first** one that matches. Put specific errors before general ones like `Exception`.
~code
def check(text, divisor):
    try:
        return int(text) / divisor
    except ValueError:
        return "not a number"
    except ZeroDivisionError:
        return "divide by zero"
    except Exception as e:
        return "other: " + type(e).__name__

print(check("10", 2))
print(check("x", 2))
print(check("10", 0))
print(check(None, 2))
@Q
Refer to the code above. Which block handles `check(None, 2)`?
~opts
* `except Exception`, because `int(None)` raises a TypeError
- `except ValueError`
- None of them, so it crashes
~why
TypeError isn't listed by name, so the general block catches it.

@C
Write `average(values)` that returns the average of a list of numbers. If the list is empty, raise a `ValueError` with the message `no values`. If any value isn't a number, raise a `TypeError` with the message `numbers only`.

def average(values):
    if not values:
        raise ValueError("no values")
    for v in values:

    return sum(values) / len(values)
