=L xhstart | Going deeper: how the browser reads HTML
@T
The browser reads your HTML from top to bottom and builds a tree of elements. It's forgiving: if you forget a closing tag, it guesses. Its guess isn't always what you meant, which is why matching tags matters.

Try removing the `</strong>` below and watch the rest of the text turn bold.
~code
<p>Torque to <strong>25 Nm</strong> before testing.</p>
<p>Then check the seal.</p>
@Q
Refer to the code above. What's the parent of `<strong>`?
~opts
* The first `<p>`
- The `<body>`
- The second `<p>`
~why
It sits inside the first paragraph.
@Q
Which characters must be written as entities, like `&lt;`, to show them as text?
~opts
* `<` and `&`
- `!` and `?`
- Numbers
~why
The browser would otherwise read `<` as the start of a tag. `&amp;` shows `&`.

=L xcstart | Going deeper: where CSS goes
@T
Three places for CSS:

**Inline:** `style="color:red"` on one element. Hard to reuse.

**Internal:** a `<style>` tag in the page.

**External:** a `.css` file linked in the `<head>`. Best for real sites, since every page can share it.

You can also group selectors with commas so they share a rule.
~code
<style>
  h1, h2 { font-family: Georgia, serif; }
  .card, .panel { padding: 10px; background: #eef; }
</style>
<h1>Title</h1>
<div class="card">Card</div>
<div class="panel">Panel</div>
@Q
Refer to the code above. What does `h1, h2` mean?
~opts
* Both h1 and h2 get the rule
- An h2 inside an h1
- Only h1s next to h2s
~why
A comma separates selectors in a group.

=L xcbox | Going deeper: margins that collapse
@T
When two block elements stack, their vertical margins don't add up. The larger one wins. This is called **margin collapse**.

Here the gap between the boxes is 30px, not 50px. Padding and borders never collapse.
~code
<style>
  .a { margin-bottom: 20px; background: #def; }
  .b { margin-top: 30px; background: #fed; }
</style>
<div class="a">A</div>
<div class="b">B</div>
@Q
Refer to the code above. How do you get a full 50px gap?
~opts
* Use padding, or a flex or grid parent with `gap`
- Add `!important`
- Use bigger numbers
~why
Margins don't collapse between children of a flex or grid container.

@T
More selectors:

`[type="email"]` matches an attribute value.

=L xceffects | Going deeper: stacking and z-index
@T
When elements overlap, `z-index` decides which is on top: higher numbers win. It only works on positioned elements (`relative`, `absolute`, `fixed` or `sticky`).

`position: sticky; top: 0` keeps a header at the top once you scroll to it.
~code
<style>
  .a, .b { position: absolute; width: 80px; height: 50px; }
