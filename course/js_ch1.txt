=U scope | Scope and the Global Object | Book section 1.7. Where a variable can be seen.
=L scope1 | Who can see this variable?
@T
**Scope** means where in your code a name can be used.

A variable made inside `{ }` with `let` or `const` only exists inside those braces. That's called **block scope**. Think of it as a box that can't be seen from outside the room.
~code
let outside = "visible everywhere";

if (true) {
  let inside = "only in this block";
  console.log(inside);
  console.log(outside);
}

console.log(outside);
@T
`var` is the older way to make a variable. It ignores blocks and only stops at functions. That surprises people, so modern code uses `let` and `const`.
~code
if (true) {
  var old = "I escape the block";
}
console.log(old);

function test() {
  var local = "stuck in the function";
}
test();
console.log(typeof local);
@P
What does this print?
~code
let x = 1;
if (true) {
  let x = 2;
  console.log(x);
}
console.log(x);
~opts
* 2
1
- 2
2
- 1
1
~why
The inner `let x` is a brand-new box that hides the outer one until the block ends. This is called **shadowing**.
@T
In a browser, the **global object** is `window`. Things like `alert` and `document` are really `window.alert` and `window.document`.

A top-level `var` or function in a regular script becomes a property of `window`. `let` and `const` don't. Too many globals cause name clashes, so keep variables inside functions when you can.

`globalThis` is the name for the global object that works everywhere.
@Q
In a regular browser script, which line creates a `window.count` property?
~opts
* `var count = 1;`
- `let count = 1;`
- `const count = 1;`
~why
Only top-level `var` attaches to `window`.
@Q
Assigning to a name that was never declared, like `total = 5;`, outside strict mode does what?
~opts
* Creates a global variable by accident
- Always throws an error
- Does nothing
~why
This accidental global is a classic bug. Strict mode, covered later, turns it into an error.
@T
**Hoisting** means declarations are noticed before the code runs. A function declaration can be called above where it's written.

A `var` is known early but holds `undefined` until its line. A `let` can't be touched before its line.
~code
console.log(sayHi());

function sayHi() {
  return "hi";
}

console.log(early);
var early = 5;

Fix the scope bug so this prints `10`. Declare `total` where the last line can see it.
~start

  if (true) {
    let total = 10;
  }
  console.log(total);
}
run();
~sol

  let total;
  if (true) {
    total = 10;
  }
  console.log(total);
}
run();
~hint
Declare total before the if block, then only assign it inside.
~out

=U maps | Maps | Book section 1.10. Key and value lookups.
=L map1 | The Map object
@T
A **Map** stores key and value pairs, like an object, but it's built for lookups that change a lot. Keys can be any type.

`set` adds, `get` reads, `has` checks, `delete` removes, and `size` counts.
~code
let stock = new Map();

stock.set("valve", 3);
stock.set("seal", 12);

console.log(stock.get("valve"));
console.log(stock.has("hose"));
console.log(stock.size);

stock.delete("seal");
console.log(stock.size);
@T
Loop over a Map with `for...of`. Each round gives you a `[key, value]` pair, which you can unpack into two names. Maps keep their insertion order.
~code
let ages = new Map([
  ["Ana", 30],
  ["Leo", 41],
]);

for (let [name, age] of ages) {
  console.log(`${name} is ${age}`);
}

=U dateobj | The Date Object | Book section 1.12. Working with dates and times.
=L date1 | Dates and times
@T
`new Date()` gives the current date and time. You can also build a specific date.

Watch out: **months start at 0**. January is 0 and December is 11. Days of the month start at 1.
~code
let launch = new Date(2026, 10, 3);

console.log(launch.getFullYear());
console.log(launch.getMonth());
console.log(launch.getDate());
console.log(launch.getDay());
@T
`getDay()` gives the day of the week, with Sunday as 0.

Set parts with methods like `setDate`, which rolls over into the next month for you.

Subtracting dates gives **milliseconds**. Divide to convert: there are 1000 ms in a second.
~code
let a = new Date(2026, 0, 1);
let b = new Date(2026, 0, 11);

let ms = b - a;
console.log(ms / (1000 * 60 * 60 * 24));

a.setDate(a.getDate() + 40);
console.log(a.getMonth(), a.getDate());
@P
What month does `new Date(2026, 1, 14)` mean? This prints the month name.
~code
let names = ["January", "February", "March"];
let d = new Date(2026, 1, 14);
console.log(names[d.getMonth()]);
~opts
* February
- January
- March
~why
Month 1 is February, because counting starts at 0.
@Q
What does `getDay()` return?
~opts
* The day of the week, 0 to 6
- The day of the month, 1 to 31
- The number of days since 1970
~why
`getDate()` gives the day of the month. The names are easy to mix up.
@C
Write `daysBetween(a, b)` that returns the whole number of days from Date `a` to Date `b`.
~start

}

~sol
function daysBetween(a, b) {
  return Math.round((b - a) / (1000 * 60 * 60 * 24));
}
~hint
b - a gives milliseconds. Divide by 1000 * 60 * 60 * 24.
~after
console.log(daysBetween(new Date(2026, 0, 1), new Date(2026, 0, 31)));
console.log(daysBetween(new Date(2026, 10, 3), new Date(2026, 10, 4)));
~out
30

=L math1 | Math tools
@T
`Math` holds ready-made math tools. There's no `new`: you call them directly.

`round`, `floor`, and `ceil` round to a whole number. `abs` drops a minus sign. `max` and `min` compare. `pow` is exponents. `sqrt` is square root.
~code
console.log(Math.round(2.5));
console.log(Math.floor(2.9));
console.log(Math.ceil(2.1));
console.log(Math.abs(-7));
console.log(Math.max(3, 9, 2));
console.log(Math.pow(2, 5));
console.log(Math.sqrt(49));
console.log(Math.PI);
@T
`Math.random()` gives a decimal from 0 up to, but not including, 1. To get a whole number from 1 to 6, stretch it and floor it.

`toFixed(2)` formats a number to 2 decimal places, and it returns a string.
~code
let roll = Math.floor(Math.random() * 6) + 1;
console.log(roll >= 1 && roll <= 6);

let price = 19.5;
console.log(price.toFixed(2));
console.log(typeof price.toFixed(2));

What does this print?

console.log(Math.floor(-2.5), Math.ceil(-2.5));
~opts
* -3 -2
- -2 -3
- -2 -2
~why
`floor` always goes down, and `ceil` always goes up, even for negative numbers.
@B
Pick a random whole number from 1 to 10.

~opts

* 10
- round

~why
`random() * 10` gives 0 up to 9.99. Flooring gives 0 to 9, and adding 1 gives 1 to 10.
