=L webjs1 | Adding code to a page
@T
**HTML** describes what is on a page. **CSS** describes how it looks. **JavaScript** makes it do things.

The `<script>` tag runs JavaScript. It can hold code directly, or load a file with `src`.

The browser reads HTML from top to bottom, so a script in the `<head>` runs before the body exists. Put scripts at the end of the body, or add `defer` to wait for the page.
~html
<h1 id="title">Hello</h1>
~code
// This runs after the page is ready.
let title = document.getElementById("title");
title.textContent = "Hello from JavaScript";
@Q
Which tag loads code from a file named `app.js`?
~opts
* `<script src="app.js"></script>`
- `<link href="app.js">`
- `<javascript file="app.js">`
~why
`src` points to the file. Keep the closing tag, even though it's empty.
@Q
A script in the `<head>` can't find an element in the body. What's the simplest fix?
~opts
* Add `defer` to the script tag
- Rename the element
- Add `await` to the HTML
~why
`defer` waits until the page has been read. Moving the script to the end of the body also works.
@Q
What does `document.addEventListener("DOMContentLoaded", start)` do?
~opts
* Runs `start` once the HTML is ready
- Downloads the page again
- Deletes the document
~why
It's another way to wait until elements exist.

=L events1 | Listening for events
@T
An **event** is something that happens: a click, a key press, typing. Instead of running top to bottom and ending, a page waits and reacts.

`addEventListener` takes the event name and a function to run. That function is called a **handler**. Run this, then press the button in the preview.
~html
<button id="go">Press me</button>
<p id="out">Not pressed</p>
~code
let count = 0;
let button = document.getElementById("go");

button.addEventListener("click", function () {
  count++;
  document.getElementById("out").textContent = `Pressed ${count} times`;
});
@T
The handler receives an **event object**. `event.target` is the element that was used. `event.key` gives the key pressed. `event.preventDefault()` stops the browser's normal action, like a form reloading the page.

Common events: `click`, `input`, `change`, `submit`, `keydown`, `mouseover`, `load`.
~html
<input id="name" placeholder="Type here">
<p id="echo"></p>
~code
document.getElementById("name").addEventListener("input", (event) => {
  document.getElementById("echo").textContent = event.target.value;
});
@Q
What's wrong with `button.addEventListener("click", doThing());`?
~opts
* It calls `doThing` right away instead of passing it
- `click` should be capitalized
- Handlers can't have names
~why
Pass the function itself: `doThing`, with no parentheses.
@Q
Clicking a button inside a `div` also triggers a click listener on the `div`. What's this called?
~opts
* Event bubbling
- Hoisting
- Shadowing
~why
Events travel up through the parent elements. Listening on a parent for many children is called **delegation**.

@T
`setTimeout` runs a function once, after a delay in milliseconds. 1000 ms is one second.

`setInterval` keeps running it on a schedule until you stop it with `clearInterval`.

Timers don't pause your program. The next line runs right away, and the timer fires later.

let id = setInterval(() => {
  console.log(n);
  n--;
  if (n === 0) {
    clearInterval(id);
    console.log("Liftoff");
  }
}, 100);

=U xhr | XMLHttpRequest and Web APIs | Book sections 2.9 to 2.11. Getting data from servers.
=L xhr1 | Asking a server for data
@T
**Ajax** means loading data without reloading the page. `XMLHttpRequest` is the original tool for it.

The app can't reach the real internet, so it answers these lessons with a built-in practice server at `api.example.com`. It has `/weather?city=Austin`, `/quote`, `/users`, `/rates`, and `/forecast?city=Austin`.

Requests are **asynchronous**: `send` returns right away, and the `load` event fires when the answer arrives.
~code
let xhr = new XMLHttpRequest();

xhr.addEventListener("load", function () {
  console.log(this.status);
  let data = JSON.parse(this.responseText);
  console.log(data.tempF);
});

xhr.open("GET", "https://api.example.com/weather?city=Austin");
xhr.send();
console.log("Sent");
@T
A **web API** is a service your code talks to over the internet, like a weather service. You read its documentation to learn the URLs, and many need an API key.

Status codes tell you what happened: 200 is OK, 404 is not found, and 500 is a server error.

Browsers block most requests to other sites unless that site allows it. That rule is the **same-origin policy**, and the allowing system is **CORS**.

Browsers also differ in what they support, so test across them. Check support before using something new. This is called **feature detection**.
~code
if ("localStorage" in window) {
  console.log("This browser has localStorage");
}
@Q

~opts
* Add the listener, `open`, then `send`
- `send`, `open`, then add the listener
- `open`, `send`, then `create`
~why
The listener has to be ready before the answer can arrive.
@Q
Your code gets a CORS error. What does that mean?
~opts
* The other server hasn't allowed requests from your site
- Your JavaScript has a typo
- The JSON is invalid
~why
The browser blocked reading the response. The other server, or your own server acting as a go-between, has to allow it.
@Q
What does a status of 404 mean?
~opts
* The resource wasn't found
- Everything worked
- The server crashed
~why
Always check the status before using the data.

=U ex2 | Chapter 2 Examples | Book sections 2.12 and 2.13. Lights Out and Weather Comparison.
=L ex21 | Lights Out game
@T
**Lights Out** is a grid of lights. Pressing one toggles it and its neighbors, and you win when they're all off.

Good programs split the **game logic** from the **display**. Here, a 2D array holds the state, and a render function draws it. Press the squares.
~html
<style>#g{display:grid;grid-template-columns:repeat(3,44px);gap:4px}#g button{height:44px;background:#222}#g button.on{background:gold}</style>
<div id="g"></div><p id="s"></p>
~code
let on = [[true, false, true], [false, true, false], [true, false, true]];

function toggle(r, c) {
  if (on[r] && on[r][c] !== undefined) on[r][c] = !on[r][c];
}

function press(r, c) {
  toggle(r, c);
  toggle(r - 1, c);
  toggle(r + 1, c);
  toggle(r, c - 1);
  toggle(r, c + 1);
  render();
}

function render() {
  let g = document.getElementById("g");
  g.innerHTML = "";
  on.forEach((row, r) => row.forEach((lit, c) => {
    let b = document.createElement("button");
    if (lit) b.classList.add("on");
    b.addEventListener("click", () => press(r, c));
    g.appendChild(b);
  }));
  let won = on.flat().every((lit) => !lit);
  document.getElementById("s").textContent = won ? "You win!" : "";
}

render();
@Q
Refer to the code above. Why does `toggle` check `on[r]` first?
~opts
* Neighbors can fall off the edge of the grid
- To make it run faster
- Arrays require it
~why
`on[-1]` is `undefined`, and reading `[c]` from it would crash.
@Q
What's the benefit of separating game logic from display?
~opts
* You change state in one place and redraw from it
- The code gets longer
- CSS stops being needed
~why
The array is the single source of truth. React and Angular are built on this same idea.

@C
When `#add` is clicked, add the text from `#item` to `#list` as a new `li`, then clear the input. Ignore empty text.

Clicking an `li` should remove it.
~html
<input id="item"><button id="add">Add</button><ul id="list"></ul>
~start
// Your code here

~sol
document.getElementById("add").addEventListener("click", () => {
  let input = document.getElementById("item");
  let text = input.value.trim();
  if (!text) return;
  let li = document.createElement("li");
  li.textContent = text;
  li.addEventListener("click", () => li.remove());
  document.getElementById("list").appendChild(li);
  input.value = "";
});
