=U rsstruct | Structs and Methods | Grouping data.
=L rs5a | Structs
@T
A **struct** groups named fields. Methods go in an `impl` block.

A method's first parameter is `&self` to read the struct, or `&mut self` to change it. A function in `impl` without `self`, like `new`, is called with `Type::new(...)`.
~code
struct Tank {
    name: String,
    capacity: u32,
    level: u32,
}

impl Tank {
    fn new(name: &str, capacity: u32) -> Tank {
        Tank { name: name.to_string(), capacity, level: 0 }
    }

    fn fill(&mut self, liters: u32) {
        self.level = (self.level + liters).min(self.capacity);
    }

    fn describe(&self) -> String {
        format!("{}: {}/{} L", self.name, self.level, self.capacity)
    }
}

fn main() {
    let mut t = Tank::new("T-1", 500);
    t.fill(120);
    t.fill(900);
    println!("{}", t.describe());
}

Add `#[derive(Debug)]` above a struct to print it with `{:?}`. That's handy while you're working.

=U rsenum | Enums, Option and match | Values that can be one of several things.
=L rs6a | Enums
@T
An **enum** is a type that's exactly one of several **variants**. Variants can carry data. `match` handles each one.
~code
enum Command {
    Open,
    Close,
    Set(u32),
}

fn run(c: Command) -> String {
    match c {
        Command::Open => "Opening".to_string(),
        Command::Close => "Closing".to_string(),
        Command::Set(p) => format!("Setting to {p}%"),
    }
}

fn main() {
    println!("{}", run(Command::Open));
    println!("{}", run(Command::Set(40)));
}
@T
Rust has no `null`. Instead, a value that might be missing is an `Option`: either `Some(value)` or `None`. You have to handle both, which prevents a whole class of crashes.

`if let` is a short `match` for when you only care about one case.
~code
fn find(parts: &[&str], name: &str) -> Option<usize> {
    for (i, p) in parts.iter().enumerate() {
        if *p == name {
            return Some(i);
        }
    }
    None
}

fn main() {
    let parts = ["valve", "seal", "hose"];
    match find(&parts, "seal") {
        Some(i) => println!("Found at {i}"),
        None => println!("Missing"),
    }
    if let Some(i) = find(&parts, "pump") {
        println!("Found at {i}");
    } else {
        println!("No pump");
    }
    println!("{}", find(&parts, "hose").unwrap_or(99));
}

~opts
* `Option` makes missing values explicit, so you can't forget to check
- Rust programs never have missing data
- `null` is too slow
~why

- None
- A crash

@B

~code

~opts

* None
- Ok
- Null
~why

`"42".parse::<i32>()` returns a `Result`, because the text might not be a number.

`unwrap()` takes the value or crashes, which is fine for quick tests. `expect("msg")` crashes with your message.

    let y: i32 = b.parse().map_err(|_| format!("bad number: {b}"))?;

}

fn main() {

=U rstrait | Traits and Generics | Shared behavior. Intermediate Rust.
=L rs9a | Traits
@T
A **trait** is a set of methods a type promises to have, like an interface in C#. Implement it with `impl Trait for Type`.

A function can accept any type that has the trait with `&impl Trait`.
~code
trait Device {
    fn name(&self) -> String;
    fn status(&self) -> String;
    fn report(&self) -> String {
        format!("{}: {}", self.name(), self.status())
    }
}

struct Valve { open: bool }
struct Gauge { psi: f64 }

impl Device for Valve {
    fn name(&self) -> String { "Valve".to_string() }
    fn status(&self) -> String { if self.open { "open".into() } else { "closed".into() } }
}

impl Device for Gauge {
    fn name(&self) -> String { "Gauge".to_string() }
    fn status(&self) -> String { format!("{:.1} psi", self.psi) }
}

fn show(d: &impl Device) {
    println!("{}", d.report());
}

fn main() {
    show(&Valve { open: true });
    show(&Gauge { psi: 450.0 });
}
@T
**Generics** let one function work with many types. `T: PartialOrd` means "any type `T` that can be compared".
~code
fn biggest<T: PartialOrd + Copy>(items: &[T]) -> T {
    let mut best = items[0];
    for &x in items {
        if x > best {
            best = x;
        }
    }
    best
}

fn main() {
    println!("{}", biggest(&[3, 9, 2]));
    println!("{}", biggest(&[1.5, 0.2]));
    println!("{}", biggest(&['a', 'z', 'm']));
}

* The trait gives a default version they both use
- `report` is private
- Rust copies it from C#
~why
Types can still override a default if they need to.
@Q
What does `T: PartialOrd` say about `T`?
~opts
* It can be compared with `<` and `>`
- It must be a number
- It's a reference
~why
It's a **trait bound**: a requirement on the generic type.
